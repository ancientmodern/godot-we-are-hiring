# 《我们正在招人》产品裁决 v1

> 日期：2026-08-29  
> 产品依据：`we-are-hiring-creative-bible.md`  
> 目的：关闭 `requirements_matrix.md` 已列出的规范歧义，并记录实现期发现的后续跨要求冲突。  
> 边界：“已裁决/文案批准进入实现”不等于“已实现”或“已验证”。

## 裁决摘要

## DEC-002：债公式与周结算顺序

全部值以浮点保存和序列化，不做每周取整。正式 UI 只显示办公室退化档位，不显示债值。

```text
N1 = clamp(N0 - 2.0, 0.0, 100.0)
gap = N1 - C

if gap > 0:
    D1 = D0 + gap * 0.20
elif gap < 0:
    D1 = D0 - min(D0, abs(gap) * 0.12)
else:
    D1 = D0

D1 = clamp(D1, 0.0, 999.0)
```

- `N0` 是本周所有玩家行动的即时效果完成后的叙事，`N1` 是每周自然衰减后的叙事，`C` 是当时能力，`D0/D1` 是本次被动结算前/后的债。
- 显式行动或剧情效果（例如 eval -5、现场兑现清零）在它们的事件解析时另行生效；不改变上述每周被动公式。
- 被动还债只在 `C > N1` 时发生，因此“让能力追上叙事”仍是真正的长期还债路径。

锁定的周末顺序为：

1. 完成本周已选行动的即时效果。
2. 叙事自然衰减 `-2`。
3. 用衰减后叙事执行上述债公式并 clamp。
4. 扣除本周 burn。
5. 更新债兑现压力并排程兑现事件。
6. 腐蚀员工信念，再做离职检查。
7. 更新本周 AI 使用连续状态、现金/连贯终局标志和作者阶段快照；新阶段的自动行为从下周 `begin_week` 生效。
8. 解析该周固定/已排程剧情，然后保存完整周状态。

## DEC-003/004：融资和 demo 的非死路分支

- 第一章第 4 周的“诚实”结果是该次会议未融到钱，不是章节失败。“夸大”或 AI 结果可得到桥接现金/推进承诺，但不替代第 8 周的正式交割。
- 第 8 周必须有一次明确的机械现金入账，数量只由当时叙事档位决定；能力不参与。
- `demo_video` 解锁后高亮它的 `叙事 +18`，但不自动执行、不停用其他卡、不用剧情要求玩家补做。
- 第二章第 6 周“现场跑一次”仍必定发生。若使用过 demo，使用“十一版/0.8 秒”正文并记录见证；若从未使用，客户改为“看过融资材料，想看现场”，不得虚构玩家做过的视频，也不设 `demo_fake` 见证标志。现场跑/推迟/AI 代理的机械分支保留。

## DEC-005/006：林越第四章分流

`lin_last_visit` 的当前正文和三选项批准进入生产实现。它只能在 `lin_present == true` 时出现。

`lin_present == false` 时必须改用以下已批准 v1 基线：

> **没有最后一次** · 第 4 周  
> 日历里原本为林越保留的十五分钟被系统自动取消。  
> 原因：参与者不再属于组织。  
> 内网起源文章还写着“我们说：先这样”。  
> 你点开她已失效的门禁记录。最后一次刷卡停在她离开的那天，凌晨一点。  
> 系统询问是否释放这个门禁卡编号。

该缺席分支仍是决策界面：提供“保留到月底”、“释放编号”和“让它来写”。AI 选项必须立即解决行政工作并给当周净好处，但不生成林越的新台词。

## DEC-007：夜班一新增文案状态

- `night_shift_1.objects.pothos`：绿萝发黄、无人记得浇水，花盆下是待审批的供应商收据。
- `night_shift_1.objects.mug`：杯底冷咖啡，杯把朝显示器；玩家只是不确定它是否更靠左。

## DEC-008：结局解析细则

1. 夜班终端只有完整输入精确字符串 `rm -rf` 时即时进入 `rm_rf`；不 trim 出额外参数，不接受大小写变体，不二次确认。
2. 除显式 `rm_rf` 外，现金储备 `<= 0` 立即解析 `lights_out`，不等到第四章。
3. 公司存活到第四章结束时，依次检查 `coherence < 20`、`author_weight >= 100`、`capability >= 80 && debt < 10`，否则为 `acquihire`。比较使用未取整的内部值。
4. `second_time` 由新游戏导演在 `completed_once == true` 时播放，播完后进入第零章第 1 周。它永远不是通关 resolver 的返回值。
5. 当前 `acquihire`、`drift`、`rm_rf` 全文及其 `final_line` 批准作为 v1 生产基线。这个批准只关闭“没有正文”的规范缺口；公司名插值、林越在场/离开语句和全文快照仍需验证。

## DEC-009：现金、runway 和 burn 换算

命名上把当前核心的 `cash_weeks` 解释为 `cash_reserve_units`，单位是“开局 burn 下的一周现金”。存档兼容期可保留原键名，但所有系统必须使用下列同一语义：

```text
cash_reserve_units = 10.0                  # 新游戏
weekly_burn_units = 1.0 + salary_burn_modifier
displayed_runway_weeks = ceil(max(0, cash_reserve_units) / weekly_burn_units)

# 每周扣款
cash_reserve_units = max(0, cash_reserve_units - weekly_burn_units)

# 事件的“现金 -15%”
cash_reserve_units = max(0, cash_reserve_units * 0.85)
```

- `现金 +N/-N` 对储备单位做加减，融资、外包和 AI 自动融资不可直接改写显示周数。
- 涨薪只增加 `salary_burn_modifier`；它不平白删除储备，而是通过更高 burn 缩短 runway。
- 储备、burn 都以浮点存档；只有 UI runway 向上取整。所有百分比都对未取整的当前储备计算。

## DEC-010：员工、士气、信念和人数

- 每个在职员工必须拥有 `id/name/role/skill/morale/belief/witnessed[]`。离职后移入 former-employees 记忆，不再参与聚合，但其见证不可丢失。
- 公司士气 `company_morale = sum(active_employee.morale) / active_employee_count`，每次人员或士气改变后立即重算。无在职员工时保留最合近的已 clamp 值，但结局不得把它当作真实员工士气。
- 公司级士气效果等量作用于每名在职员工后再重算平均；个人事件只修改对应员工。
- 团队人数是 `1 + active_employee_count`。林越在职时属于 active employees；玩家创始人是额外的 `1`，不创建可见姓名或个人士气。
- 信念始终按员工个体腐蚀和触发离职；团队可以在 UI 中显示个人信念，但不得显示一个虚构的公司“平均信念”作为核心指标。

## DEC-012：陈小雨回忆的可达时序

策划写“裁掉了陈小雨 → 三章之后，谈到数据质量时”，但同一策划把裁员锁在第三章第 2 周，而普通战役在第四章结束；字面路线没有三个后续章节，因而不可达。生产基线把“章”裁决为“周”：

- 记录陈小雨被裁的绝对周；`+1`、`+2` 周不触发。
- 从 `+3` 周开始，玩家首次执行清洗数据、做 eval 或训练一轮时，模型引用她修过的 pipeline 与仍在运行的校验规则。
- 回忆只出现一次，存档/读档不得重置；未裁掉她的路线永不触发。
- 此裁决只修复不可达的时间单位，不改变策划给定的陈小雨入职、一对一和两种离职原话。

## DEC-013：eval 与公开能力值

能力是七个核心状态中的公开值，从开局起持续显示；隐藏它会破坏玩家判断“叙事与实际能力距离”的基本决策。因此 `做 eval` 的“揭示真实能力值”采用下列生产解释：

- 行动前后能力数值都保持可见，不做一次性解锁，也不设置限时遮罩。
- 首次 eval 把当前可见读数标记为经过正式评测核验，并在历史/存档中保留 `capability_revealed`（语义为 verified）。
- 首次人工行动按规范执行债 -5；首次 AI 委托版本叠加通用即时收益后为 -8。两者都只核验能力，不增加能力。
- 已有 `capability_revealed` 后仍可重新跑曲线，但只更新核验记录并照常消耗算力/人工注意力；人工和委托版本都不再减债，委托版本也不得虚构能力增益。这样保留评测工具，同时关闭每周廉价清债循环。
- UI 与行动说明使用“核验”而非“第一次看见”，并在重复核验时明确不再抵消既有承诺，避免与公开指标或实际效果冲突。

## DEC-014：独家专访的高债抽签

- `debt <= 55`：不消耗 RNG，固定叙事 +20。
- `debt > 55`：从战役保存的 RNG 取一次 `[0,1)` 样本；样本 `<0.45` 时为负面报道（叙事 -8、连贯 -5），否则仍为叙事 +20。
- RNG 状态在抽签后立即进入完整存档。相同抽签前存档必须复现相同报道，不能使用系统时间或未保存的 `RandomNumberGenerator`。

## DEC-015/016/017：通用写作规则的封闭例外

通用 AI 委托仍以“当周更省事、长期失去作者身份”为核心。只有策划明确给定效果的林越关系场景可以在同一选择中降低信念或安排离职；这些分支必须原样展示关系代价，不能再叠加一个惩罚 toast。

`签字` 的动画是行政完成，不产生核心数值、关系或剧情 flag。正常周流程仍需记录它已执行、扣除人工注意力或占用一次委托、写入审计 history；这些字段只用于可恢复的动作生命周期。委托签字不增加作者权重，也不添加“AI 更好”的舒适奖励。

AI 按钮例外只允许：`second_time` 双选、`LIN-004B` 三个手写回答、`never_delegated` 自反提问，以及拿/看/放杯子这类纯交互阶段。任何新增例外都必须新增产品裁决，不能临时加入测试白名单。

## DEC-018/019：第一版价值观与自由周数据形态

v1 的使命只有一句；同一文件可以有第二条操作承诺。模型语料、内网归档和关灯结局都必须读取同一个永久 v1 条目，不能为结局临时拼出不存在的旧文本。

策划所说的“自由/无事件周”表示没有必须弹出的剧情，而不是数据表缺少该周。生产数据为每周保留一个幂等 fixed key；这些周的 `silent` beat 不显示 modal、不播放声音，也不吞掉满足条件的正常随机事件。

## DEC-020：认真训练门槛

只统计真正运行训练的 `train` 与 `large_train`，不把 eval、清洗数据、招专家或 AI 行政算成训练。两者累计至少 3 次且作者权重 `<60`，才展示林越带两罐啤酒的温暖路线。计数来自永久 `action_counts`，跨周、跨章、读档均不重置；训练不足时仍给完整的诚实手写场景，但不获得温暖路线的关系恢复。

## DEC-021：裁员人数与 burn

- 选择顺序为信念从低到高，稳定同值按员工 ID；林越不进入通用裁员池。
- 最多移除 6 人；不足时移除所有可移除员工。每名离职者保留自己的见证和离职文案快照。
- `burn_rate -2` 乘既有 0.25 换算，使 `salary_burn_modifier` 降 0.5。`weekly_burn = max(0.25, 1 + salary_burn_modifier)`，存档加载使用同一下限。

## DEC-022：窗外工位的 37 人算式

第四章异常周的系统在场构图锁为 `inside_presence=33`、`outside_presence=37-33=4`。组织架构显示 37，工资表显示 36；窗外只渲染算出的 4 个普通工位，不额外制造第 38 个身份，也不把隐藏作者权重解释成“幽灵人数”。

## DEC-023：LIVE-006 与无脸主角的优先级

`WORLD-008` 是贯穿全游戏的硬性构图约束，优先于把 `LIVE-006` 的“口型对得上”误读为必须直接绘制嘴或脸。会议录像必须明确呈现主角确实在镜头中说话：画面裁到脸以下，显示同一具身体与手势、字幕、波形、进度条，以及“我们”之后字幕和波形同时停顿；正文由主角观察并确认“口型对得上”。这里的口型一致是被写出的可靠观察，不是可见嘴部动画。任何版本都不得为证明该句而显示主角的嘴、脸或可识别人物立绘。

这一裁决不削弱 `LIVE-006`：玩家仍亲手经历签约、第一次播放、异常停顿、拖回去重看和“讲得真的很好”的承认；它只规定在不违反 `WORLD-008` 的前提下，录像式界面用哪些可见证据承载同一事件。

## DEC-024：雨印档案取代通用后台壳层

经营主循环是一册真实存在于办公室桌面的公司档案：左侧封套承载索引，中间冷档案纸承载周行动，右侧夹纸承载批注。五项公开状态必须是一条连续总账，而非五张 KPI 卡。人物戏离开经营壳层，以未经灰白蒙版冲淡的全屏场景和一张暖人纸承载正文；只有 LANTERN、内网、董事会、录像等叙事上本来属于软件/机器的页面使用深色机器玻璃。文档圆角 0–3px，列表行只用规则线和装订线，不允许卡片套卡片。

Noto Sans SC 用于系统与数据，Noto Serif SC 用于事件标题、人的文档与结局。所有新增资产必须原创或按授权清单进入 manifest；只借鉴参考作品的高层触感与经营/人戏对照，不复制其布局、角色、图标、文案、配色、音乐或动画。

## DEC-025：克制配乐、场景声与物理拟音

- 三个核心办公室 ambience 仍为空调、键盘、远处说话声；服务器风扇是地点性的 diegetic stem，不常驻所有页面。咖啡馆、开场、会议室、夜班和结局必须拥有正确的 room-tone 策略。
- 作者权重 35–85 时键盘从松散连续交叉到同步；跨过阈值不使用 stinger、文字或 UI 提示。第四章按周逐渐抽走人声与空调，在最终周只剩同步键盘。
- 允许两条程序化原创、长留白的配乐 stem：`human` 与 `system`。平均电平必须低于房间底噪约 8–12 dB；事件、夜班、静默页与异常默认 duck 或完全静音，不做胜负、奖励、恐怖或揭秘判断。
- 允许非循环 one-shot 物理拟音：纸张选择/翻页、铅笔确认、印章结算、机械键委托、门锁、杯子等。只从玩家明确动作函数触发，不从 `_draw()`、状态恢复、自动保存、隐藏数值变化或异常出现触发；禁止 hover 连响、移动端 beep、奖励 jingle 和章节 stinger。
- 静音策略是一等状态：`normal`、`duck_music`、`room_tone_only`、`full_silence`。林越指定沉默页、silent beat、异常与作者阶段变化必须验证无 cue。

## DEC-026：林越静默的叙事时间与真实时间

`LIN-002` 保留原文中两次“大概两分钟”的故事内时间，也保留五拍结构和两个互不合并的空白页。考虑到它发生在约一小时的首轮体验中，普通模式把每个 120 秒故事时间段演出为 10 秒不可跳过的真实静默；这不是删除停顿，而是明确的时间压缩。降低动态效果同时承担可访问性跳过职责，将每段门槛缩短到 0.15 秒。两种模式都不播放配乐、拟音、倒计时提示声或特殊 cue；唯一可见反馈是纸面上的安静等待状态。

## DEC-027：主角与林越的固定过去及未来关系系统

七年前，两人在大学交换项目中认识，并在 314 教室共同完成一次通宵课程项目；回宿舍的路口，两个人都比告别需要的多站了一会儿，但从未正式在一起。现在他们是联合创始人，亲近、互相信任，也各自保留没有说破的部分。开场可以有熟人式调侃、停顿和轻微 flirt，但不得让林越失去 CTO 的专业判断、独立目标和拒绝玩家的权利。

当前版本只写入隐藏的多维关系种子与关键选择记忆，不显示“好感度 +1”。未来感情系统至少同时检查长期信任、共同价值、工作边界、默契/温度和林越的独立状态；任何恋爱路线必须允许自然不发生，也不能用现金、估值或一次正确选项直接兑换。
