# 《我们正在招人》完整需求与验收矩阵

> 状态：实施前基线（所有条目默认 **未验证**）  
> 唯一产品规范：[`we-are-hiring-creative-bible.md`](../we-are-hiring-creative-bible.md)  
> 用途：把策划案转成可实现、可追踪、可逐项举证的完成标准。本文不是策划摘要，也不因当前原型的能力而缩小范围。
> 当前构建的 272 项逐条审计结果：[`requirement_evidence_ledger.md`](requirement_evidence_ledger.md)

## 0. 审计约定

### 0.1 完成状态

| 状态 | 含义 |
|---|---|
| 未实现 | 权威运行态中不存在该要求。 |
| 已实现，未验证 | 代码或内容存在，但没有与要求同范围的证据。 |
| 部分完成 | 仅覆盖部分分支、周目、章节、数值区间或表现层。 |
| 已验证 | 源码/内容、自动化测试、运行日志、视觉或听觉证据共同证明要求成立。 |
| 规范待决 | 原策划内部存在空缺或冲突；不得擅自删减，需保留并形成明确产品决议。 |

本文创建时不以“文件存在”“测试未报错”推定完成。所有要求必须在完成审计时逐项填入状态和证据链接。

### 0.2 权威证据层级

1. **确定性系统测试**：固定随机种子和存档状态，执行到目标周/分支，断言状态、数值、事件、文本键和结局键。
2. **内容注册表校验**：验证所有章节、周、行动、林越场景、夜班热点、异常、记忆引用、结局和本地化文本均被引用且可达。
3. **运行时捕获**：Godot 实际构建的截图、逐帧录像、音频 stem/频谱、输入回放、存档往返和日志；不能用设计稿代替。
4. **人工叙事 QA**：核对文案、沉默、无提示、角色语气、镜头/界面边界以及不能被普通断言覆盖的节奏。
5. **真实玩家验收**：只用于策划明确要求的体验指标；内部主观判断不能替代玩家数据。

建议证据目录：`tests/evidence/<requirement-id>/`；每项至少包含测试名或操作步骤、构建版本、随机种子、输入序列、预期、实际和产物路径。

## 1. 建议 Godot 架构（实现目标，不是当前完成声明）

### 1.1 场景和服务边界

| 模块 | 建议职责 | 关键不变量 |
|---|---|---|
| `Main.tscn` / `GameShell` | 永久世界内档案桌外壳；加载周总账、人员卷宗、LANTERN、日历、公告和夜班界面。 | 经营操作留在档案桌；人物戏切到 full-bleed 场景；只有叙事上真实存在的软件保留软件界面。 |
| `GameState`（autoload） | 章节、周、注意力、七项核心状态、团队、公司名、标记、作者权重阶段、NG+ 状态。 | 所有分支由可序列化状态决定；不把关键状态藏在 UI 节点。 |
| `WeekDirector` | 周开始/行动/周结算/固定事件/随机事件/章末的确定顺序。 | 固定周事件不可被随机事件顶掉；叙事每周 -2 和债累积顺序有测试。 |
| `ActionSystem` | 行动池、注意力消耗、效果、临时 buff、互斥条件。 | 每周五个想做事项、三点注意力；每个决策支持“让它来写”。第四章使用独立受限池。 |
| `NarrativeDirector` | 事件条件、选择、文本变体、作者口音、林越场景、模型记忆引用。 | 内容由稳定 ID 驱动；所有要求分支可由测试直接进入。 |
| `AuthoringSystem` | “让它来写”的效果、作者权重、五阶段行为和自动操作。 | 每次使用净体验必须变好；阶段三开始只改变文字而不弹提示。 |
| `DebtSystem` | 债生成、视觉映射、兑现事件调度和还债。 | 债数值永不直接显示；办公室视觉和事件频率是唯一常规反馈。 |
| `CompanySystem` | 现金/burn/剩余周、算力、融资、团队聚合、招聘裁员。 | 融资判定只读叙事，不读能力。 |
| `EmployeeSystem` | 姓名、技能、士气、信念、见证记录、离职文案。 | 见证历史持久化，陈小雨干净/见证造假的离职内容互斥。 |
| `OfficeAnomalySystem` | 租约边界、系统记录与异常实例、窗帘回弹、D 室、额外楼层/工位/员工。 | 异常不追逐、不说话、不解释；反应只能是行政性的。 |
| `NightShiftController` | 极简平面图、点选移动、热点、终端命令、夜班一/二。 | 热点可达；`rm -rf` 无确认；不把夜班做成恐怖追逐。 |
| `EndingResolver` | 七结局条件、优先级、结局内容和周目完成记录。 | 相同存档必然得到相同结局；NG+ 不与普通结局误判。 |
| `SaveService` | 公司名、全状态、见证、林越状态、已通关、NG+ 杯子状态。 | 退出/加载不改变周、随机结果和隐藏值；公司名在结局替换。 |
| `AudioDirector` | 空调/键盘/远处说话三层白噪音，章节混音，同步键盘。 | 没有提示音和过场音乐；第四章只剩整齐键盘。 |
| `ContentRegistry` | `.tres`/JSON/Resource 内容索引及可达性验证。 | 启动测试能列出所有 requirement ID 对应的内容键，禁止孤儿文本。 |

### 1.2 推荐状态机

`BOOT → CHAPTER_OPEN → WEEK_START → ACTION_SELECTION → ACTION_RESOLUTION`（每点注意力循环）`→ WEEK_END_SYSTEMS → FIXED_EVENT/RANDOM_EVENT → WEEK_RECAP → CHAPTER_END → NIGHT_SHIFT（指定章）→ ENDING → CREDITS → NEW_GAME_PLUS`

- `WEEK_END_SYSTEMS` 的固定顺序应被锁定为：行动效果完成 → 叙事自然衰减 -2 → 债累积 → 员工信念腐蚀/离职检查 → 兑现事件排程 → 作者权重阶段检查 → 存档。
- 若最终设计采用不同顺序，必须更新 DEC-002 并为边界值编写回归测试。
- 固定事件使用 `(chapter_id, local_week)` 键；随机事件只能填“自由”周或固定事件允许的附槽。
- 所有文字使用稳定键而非直接散落在绘制代码中；公司名、员工名、数值和“我们”的特殊停顿通过受控 token 注入。

## 2. 世界、角色与基调要求

| ID | 具体实现要求 | 权威验证证据 |
|---|---|---|
| WORLD-001 | 时间是“现在”，地点是现实湾区；外部物件、日期、办公方式和融资语境不得暗示科幻或近未来。 | 内容检索无未来年份/科幻技术；全章节人工文案 QA；外部场景截图。 |
| WORLD-002 | AI 能力严格等同现实常见水平：能写邮件、总结会议、演示惊艳、真实使用令人失望。不得觉醒、出现奇点或机器人。 | 全内容禁用词/语义审查；模型输出事件集人工核对；无机器人/意识揭露资产。 |
| WORLD-003 | 唯一不现实的元素是办公室及其行政系统延伸。 | 全异常内容注册表逐项证明 `location=leased_office` 或软件界面映射；外部场景运行捕获正常。 |
| WORLD-004 | 公司默认名为“提灯实验室 / Lantern Labs”；玩家可改名，存档记住，并在所有适用结局中使用玩家公司名。 | 新建时改名→存档→重启→进入七个结局的参数化测试；截图显示替换名。 |
| WORLD-005 | 公司起源是转租联合办公工位、两个人、一张显卡；第一版价值观的唯一使命句是“做一个能听懂人在说什么的东西。”，同一归档含“如果做不出来，就说做不出来。”，且第一版始终保留在模型语料中；见 DEC-018。 | 开场/起源文章/关灯/独立相关文本键核对；存档状态含 `values_v1_in_corpus=true` 且不可被后两版清除。 |
| WORLD-006 | 模型命名按章安静缩短：第 0 章 `lantern-v0.1`/私称“那个模型”；第 1 章 `lantern-v0.4`/“阿灯”；第 2 章 `lantern-v1`/“阿灯”；第 3 章 `Lantern`/“阿灯”；第 4 章 `LANTERN`/不再有人用昵称。 | 逐章 UI 与对话快照；第 4 章全内容检索无“阿灯”；版本消失周没有 toast、弹窗、音效或说明。 |
| WORLD-007 | 版本号消失的那一周不做任何显式提示。 | 输入回放对比第 3 章末/第 4 章周 1，只允许材料文字自然变更；通知队列为空。 |
| WORLD-008 | 主角无名、无脸；姓名、外貌、家庭与交换经历之外的个人背景留白，全程不出现自己的脸或可识别人物立绘。唯一固定过去是与林越共同经历的大学交换项目，见 WORLD-011 与 DEC-027。 | 资产与场景审计；全流程截图；存档无主角姓名/外貌/家庭字段，只允许关系历史种子。 |
| WORLD-009 | 主角表现为观察力过剩、行动力不足，典型行为是注意杯子移动两厘米；不得变为主动调查超自然。 | 夜班二工位文本和所有异常反应文案核对；无“调查真相”行动。 |
| WORLD-010 | 主角唯一明确特质：说到“我们”后从不停顿；第二章现场事件 AI 代理时以非本人停顿暴露。 | 现场跑 C 分支含精确线索；其他配音/文本节奏不得建立相反习惯。 |
| WORLD-011 | 林越是联合创始人、CTO，也是主角在创业之前就认识的旧识；两人共事或同学过，彼此有过没有说破的吸引力、从未正式在一起。相识的具体经过由出身决定（见 LIFEPATH-002），但“旧识、未说破、她先相信这件事”三点在三条出身下都成立。她是开局第二个人，也是唯一贯穿主线的具名角色。 | 员工/角色 registry；车库场景的共同过去段落按出身展开；章节事件表；除林越外不新增同等主线具名角色。员工可有名字但不取代该功能。 |
| WORLD-014 | 林越与主角的潜在感情线只作长期关系铺垫：熟人式调侃、停顿和选择记忆可以出现，但不在开场显示好感度、不强迫恋爱，也不把林越写成经营奖励。未来关系系统必须同时检查信任、共同价值、边界与她的独立目标。 | 开场选择写入持久关系种子；对白语气审读；未来系统不得只用单一好感数值解锁。 |
