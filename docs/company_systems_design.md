# 公司经营系统设计：从“更多事件”到可推演的组织

> 状态：2026-08-29 已实现并进入本地开发构建  
> 范围：资本市场、竞品、招聘与组织、办公室、SaaS 采购、政策以及系统事件调度  
> 原则：增加相互作用的状态，不增加彼此无关的按钮；压力必须能被玩家的可见成果化解，幽默服务于人物与经营处境，不破坏世界观

## 1. 为什么这样扩展

优秀的模拟经营游戏通常不是靠选项数量制造深度，而是让同一个决定同时进入多个系统：今天用高估值换控制条款，会改变下一轮稀释和董事会；今天用高薪抢人，会改变招聘胜率、内部薪资压缩和 burn；今天拿政策项目，不会立即等于现金，而会产生里程碑、验收、应收和公开承诺。

本次参考的不是某一款游戏的表面布局，而是几类成熟设计方法：

- *Software Inc.* 把产品、员工技能、团队、办公室与市场放在同一经营周期里；
- *Capitalism Lab* 强调竞争者与共享市场，而不是只让玩家在真空里升级；
- *Game Dev Tycoon* 用清楚的产品周期和事件节奏维持可读性，避免每个系统都成为常驻表格；
- *Big Ambitions* 让办公室、租赁、采购和实际容量成为增长的物理约束；
- *Football Manager* 的招聘价值来自候选人信息不完整、结构化评估、竞争 offer 和时间窗口，而不是“点击后人数 +1”；
- *Democracy 4* 的政策结果来自多变量反馈与延迟，不是一次性的声望奖励；
- *Offworld Trading Company* 证明具名竞争者必须在同一个市场中行动，玩家的价格、人才和机会成本才有意义。

现实规则部分采用官方一手资料作为语义边界：YC post-money SAFE 与 NVCA 模板用于融资结构；Greenhouse structured hiring 用于 scorecard 与面试证据；SBIR 与 California Competes 用于“拨款/税收抵免不等于立即现金”；Slack、GitHub 计费与 NIST 供应商尽调用于 seat、用量、期限、权限和续约。

## 2. 当前系统闭环

```text
产品发布 / 客户交付
        ↓
MRR、ARR、毛利、市场需求 ←→ 三家持续行动的竞品
        ↓                         ↓
真实 USD burn 与 runway       价格压力、人才压力、政策竞争
        ↓                         ↓
融资条款 → SAFE / priced round / cap table / 董事会
        ↓                         ↓
招聘计划 → 候选人 → 结构化面试 → 竞争 offer → notice → onboarding
        ↓
经理跨度、培训、调动、晋升证据、倦怠与离职风险
        ↓
办公室容量 / 装修工期 / SaaS seat、用量、权限、续约
        ↓
更高固定承诺与下一轮经营压力

政策层横跨全图：grant、tax credit、政府 pilot、公开征求意见、
行业联盟与透明登记游说分别改变现金、承诺、准入、信任与规则。
```

旧叙事层的债、能力、叙事与作者权重仍负责 45 周故事和结局。第一次扩展经营行动会把旧 `cash_weeks` 所表达的 runway 对齐到 USD 账本；从这一刻起，USD 账本是经营现金的唯一权威。旧主线之后产生的现金变化只通过带稳定 transaction id 的桥接交易进入账本，不会再形成第二套可花现金，也不会因读档或重复结算而到账两次。这样旧存档与原结局仍兼容，而融资、采购、工资、办公室和政策回款都进入同一套真实结算。

## 3. 已实现内容

### 资本、投资人和治理

- 整数股份 cap table：创始人、林越、期权池、员工期权与投资人；所有 ownership basis points 合计严格为 10,000。
- Post-money SAFE、priced Seed/A 轮、SAFE 转股、期权池交割前后扩充、董事席位；SAFE 报价会先生成 pro-forma cap table，让玩家在签字前看到转股与新钱共同造成的稀释，而不是只看 headline valuation。
- 1x non-participating preferred 退出 waterfall；每位优先股投资人分别比较清算优先权与转普通股所得，再按更高者结算，剩余价值才进入普通股分配。
- 4 名具名投资人，具有支票范围、投资主题、尽调重点、控制偏好、信任和董事会支持。
- 每笔现金或股份交易使用稳定 transaction id；读档或重复提交不会重复到账/增发。
- 融资报价只读取 `stage + narrative`；技术能力不能神奇地改变 VC 报价。能力只影响 grant、pilot 和履约。
- 员工期权采用 52 周 cliff、208 周完全归属；离职结算按在职周数计算已归属部分，未归属股份以幂等交易退回期权池。旧员工在经营层激活时会补齐真实 grant，新入职员工在进入正式 roster 时自动授予。

### 竞争市场

- Morrow AI、Chorus Systems、HarborDesk 三家稳定竞品，各有研究优先、叙事优先、企业销售优先的策略权重。
- 每周独立推进产品发布、融资、价格、企业客户、抢人和政策联盟，并产生可见 market tape。
- 市场 RNG 独立存档；竞品随机行动不会直接扣除或增加玩家现金。
- 玩家产品发布会增加客户、MRR、ARR 与品类需求，随后在同一周结算中接受竞品响应。

### 招聘、人才竞争与组织

- 8 名手写候选人，包含当前公司/职位、经验、地区、notice、目标现金与期权、技能证据、未知项、面试原话以及具名竞争 offer。
- 完整管线：requisition 与 salary/equity band → screen → work sample → panel → offer → 竞争报价判断 → notice → 正式 roster → onboarding ramp。
- 正式入职后由主模型取得员工所有权，资本模型同时发放真实 option shares。
- team、manager span、汇报线、跨组调动、培训、晋升、burnout、flight risk 与成长满意度均为持久状态。
- 结构化 scorecard 只使用岗位证据，不存储或使用受保护个人属性。
- 同一周出现多人离职时，导演只展开一个具名离职弧，其余人进入一份合并 HR 摘要；信息和系统后果都保留，但不会用成串弹窗惩罚已经处于压力中的玩家。

### 办公室与采购

- 3 类租约：联合工位、转租层、直接租赁；包含押金、法定容量、期限、周租、搬入时间与装修补贴。
- 4 类装修：安静舱、培训室、演示间、弹性工位；容量和功能存在明确取舍并需要工期。
- 4 个虚构 SaaS：代码、协作、观测、HRIS；支持 per-seat、usage、minimum seats、overage、年付、自动 provision、续约和取消窗口。
- 入离职会自动改变账户与 seat；办公室押金、装修和年付费用进入 commitment，再由周结算付款。
- 经营台账分别显示 payroll、benefits、rent、SaaS、training、compute 与 policy 成本，不把所有费用压成一个“burn -1”。
- 免租谈判不是文本奖励：免租周数、房租抵扣和生效周期进入周度 burn。转租同样会实际减少可用席位、增加周度转租收入并降低净租金；保留容量、共享门禁或独立门禁因此成为真实取舍。

### 政策与政务关系

- 非稀释研发 grant：申请评分、首笔拨款、技术里程碑和尾款。
- Jobs tax credit：记录未来岗位/投资承诺和递延抵免；没有应税利润时不会伪装成现金。
- 政府 pilot：先交付、后验收付款，能力决定能否完成。
- Public comment：可支持更强披露、行业弹性、委托或弃权；意见在未来周解析。
- 行业联盟和 registered lobbying 增加准入与影响力，同时增加持续成本和公开披露。
- 公司规模与影响力上升后可以参与规则制定，但不能凭一个按钮直接“控制政府”。
- 当玩家已加入联盟且团队达到 8 人，Chapter 4 Week 5 会保证触发行业标准草案的回报节点，而不是把长期政策投入藏在低概率抽奖里；立场、签署、准入、影响力、可信度与信任都会持久写入政策状态。

### 事件与节奏

- 39 个手写经营事件，覆盖资本、市场、人才、组织、办公室、SaaS 和政策七个 family。
- 每个事件有 3 个有代价的选择，其中保留“让它来写”作为原作作者性主题的系统性诱惑。
- 固定 45 周主线优先；经营事件是 overlay，通常每周最多一个，Chapter 0 不出现，最终三周停止出现。
- 事件按 chapter、family、actor、recent ring、cooldown、once-per-run 与 pity 选择。
- 被选中的具体事件立即 materialize 并存档；读档不会重抽一个更有利的结果。
- scheduler、市场、政策和招聘分别拥有独立 RNG，避免一次招聘面试改变下一周竞品融资。
- 除 39 个手写事件外，融资、候选人、办公室、SaaS、竞品与政策的真实状态也会生成 runtime 系统事件；每周最多安排一个 runtime 侧决策，并把选择后的候选人条款、现金、经理、租约或政策变化写成可见系统回执。
- 周结算会明确显示毛利、成本、现金变化与 runway，并报告入职、培训完成、搬家、装修和续约；首次付费客户、MRR 10K/50K/100K、团队 5/10 人、首间办公室、首笔 grant 与政府供应商资格会生成持久里程碑。
- 节奏遵守“压力—行动—回执—喘息”：风险必须可读，成功必须被看见。幽默只落在账单、行政、团队日常和庆祝回执等合适位置，以克制的一句话调节呼吸，不把困难写成闹剧，也不让所有安静周都显得阴沉。

## 4. 玩家可执行的新动词

经营行动池新增六张策略卡，并保持原 26 张行动与旧存档契约不变：

1. 安排一次产品发布；
2. 推进关键招聘；
3. 审查工具栈；
4. 做组织复盘；
5. 重做办公室计划；
6. 申请研发扶持。

每张卡先产生一个确定的经营动作，再可能让相关系统在本周结束前提出一个具体决策。它们不是“打开一个百科页面”的入口。

行动可用性由系统状态决定：已有 pending offer、候选池为空、培训仍在进行、租约已签但尚未搬入、办公室方案已完成或 grant 已提交时，对应按钮会禁用并显示具体原因。玩家不会为一个注定无效的点击浪费本周行动。

## 5. 信息设计与防过载

- 默认周界面仍然只有行动卡与一个可能出现的侧决策；详细状态集中在冷色经营台账。
- 台账第一层只显示现金、net burn、MRR/ARR、runway、创始人持股、招聘漏斗、办公室占用、成本拆分、竞品和政策状态。
- 具体候选证据、投资人条款、续约窗口与事件后果只在相关决策中出现。
- 所有关键数字必须来自模型 `public_state()`，UI 不重新计算经济结果。
- 延迟价值使用正确名词：tax credit 是递延资产，pilot 是验收后应收，SAFE 是未来稀释，不统一写成“现金 +N”。
- 结果页同时承载叙事后果和真实系统回执；产品发布、人才签约、政策承诺或办公室决策不再只改变后台状态。结局页也会回看现金、MRR、客户、团队、办公室与政策成果，确认这些成绩确实由本局经营建立。
- 常规员工在入职当周有清晰的绿色状态标记；稳定经营的安静周也会获得一条不过度庆祝的正反馈。视觉和文案共同告诉玩家“这一步有效”，而不是只在失败时发声。

## 6. 自动化证明边界

新增专用回归覆盖：

- 资本/市场/政策：411 checks；
- 招聘/组织/办公室/SaaS：584 assertions；
- 系统事件调度：141 checks；
- 39 个事件与六张策略卡内容契约：1,003 checks；
- 跨模型纵向联调和存档：199 checks；
- 系统选择纵深与真实状态分支：100 checks；
- 原模型：1,940 checks；
- 完整 45 周导演流程：2,067 checks；
- UI 导演流程与交互契约：622 checks；
- 12 个种子、3 种策略、540 个经营周的严格系统 soak：12,744 checks；每个系统事件都要求深层 `system_result.ok == true`，并持续验证现金非负、cap table 10,000 bp、年付 SaaS 不重复扣款、竞品融资上限和单周 runtime 决策预算。

长测产物见 `tests/hiring_company_systems_soak_test.gd` 与 `artifacts/company_systems_soak.json`。最终 12 局均走完 45 周；正式招聘、四类 SaaS、办公室、里程碑和融资链均实际出现。测试曾捕获候选人反报价与办公室超容的两个“外层成功、深层 no-op”，修复实时前置条件与在途容量计划后，从头重跑为 0 次深层失败。

自动化可以证明钱、股份、期限、随机状态和存档没有自相矛盾，不能证明玩家觉得取舍有趣。下一轮真人测试应特别记录：

- 玩家是否能在不查说明书的情况下区分现金、ARR、税收抵免与未验收合同；
- 第一次竞争 offer 是否让候选人感觉像人，而不是一组属性；
- 一个经营事件是否挤压了主线情绪；
- 玩家是否会因为续约、管理跨度或稀释主动改变下一周计划；
- 台账是否在 10 秒内回答“钱花在哪、下一件危险的事是什么”。

## 7. 暂不继续堆的系统

当前不新增股票二级市场、供应链、诉讼、全球税务、多币种、详细会计三表或可自由摆放家具。它们只有在现有循环的真人测试证明需要新的决策杠杆时才进入范围。下一优先级是客户 cohort / churn / pricing 与董事会正式表决，因为这两项能同时连接产品、市场、现金、投资人与组织，而不是孤立增加页面。
